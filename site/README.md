# site/

Static download website for SIDM. Plain HTML and CSS: no framework, no build step, no JavaScript, no tracking, no external requests (fonts are the system font stack).

| File | What |
|---|---|
| `index.html` | Home: animated hero with the downloads, "Works with" strip, numbers, product cards, the interactive How to use demo (extension, Windows, Android), the two parts with features and install steps, guides, FAQ |
| `assets/home.css`, `assets/home.js` | Home page only: animations (all inside `prefers-reduced-motion: no-preference`), scroll reveals, count-up numbers and the demo's tabs, steps, auto-play and "Try it" hot spots. The page works without the script |
| `guides.html` | Index of the how-to guides |
| `download-*.html` | One how-to guide per site (Facebook, Instagram reels, TikTok, X, LinkedIn, Reddit, Vimeo, YouTube): computer steps, Android steps, tips, FAQ with FAQPage schema |
| `sitemap.xml`, `robots.txt` | Generated by `python scripts/build_sitemap.py` for https://sidm.online, which also writes each page's canonical and Open Graph tags (`<!-- seo:start -->` block). Run it again after adding a page |
| `assets/og-card.jpg` | 1200x630 image shown when a page is shared |
| `_redirects` | Cloudflare Pages: sends the old `/downloads/<apk>` addresses (used by the Android app's updater) to the GitHub Release. Written by `scripts/release.py --apk-dir` |
| `privacy.html` | Privacy policy (no data collected, what stays local, permissions explained) |
| `terms.html` | Terms of use |
| `assets/site.css` | All styles. Light and dark via `prefers-color-scheme`, accent `#5546f5`, mobile layout at 640 px |
| `assets/icon-*.png`, `favicon-16.png` | Copies of the extension icons |
| `assets/popup-*.png` | Popup screenshots, generated by `scripts/test_site.py` (do not edit by hand) |
| `downloads/` | The release ZIPs and setup .exe (added by `scripts/release.py`). Every file in `site/` must stay under 25 MiB (Cloudflare Pages' limit; `scripts/check_site_size.py` checks it), so the Android APKs live in the GitHub Release `v<version>` instead |
| `vercel.json` | `{"cleanUrls": true}` |

## Release values

The download block in `index.html` is filled in by the release script through `data-release` attributes. Keep them, and keep their contents plain text:

- `data-release="extension-zip"`: `href` becomes `downloads/sidm-v<version>-extension.zip` (the main download: the extension alone)
- `data-release="version"`: text is the version (may appear more than once)
- `data-release="extension-size"`: text like `1.2 MB`
- `data-release="extension-sha256"`: hex SHA-256 of the ZIP
- `companion-windows-*` and `companion-macos-linux-*`: the same for the optional companion ZIPs

Until the first release the page shows placeholders (version 0.1.0, "size to be confirmed").

## Screenshots

`python scripts/test_site.py` loads `extension/` in Chromium, opens the real popup and saves `assets/popup-downloads.png` (light) and `assets/popup-this-page.png` (dark), quantised to 64 colours. Re-run it whenever the popup changes. They currently show the M1 popup (empty states) and are placeholders for the finished UI.

## Before launch

- Replace the placeholder contact email `contact@example.com` in `privacy.html` and `terms.html`.
