# site/

Static download website for SIDM. Plain HTML and CSS: no framework, no build step, no JavaScript, no tracking, no external requests (fonts are the system font stack).

| File | What |
|---|---|
| `index.html` | Home: hero with the Windows download, popup screenshots, features, install steps, SmartScreen note, FAQ |
| `privacy.html` | Privacy policy (no data collected, what stays local, permissions explained) |
| `terms.html` | Terms of use |
| `assets/site.css` | All styles. Light and dark via `prefers-color-scheme`, accent `#5546f5`, mobile layout at 640 px |
| `assets/icon-*.png`, `favicon-16.png` | Copies of the extension icons |
| `assets/popup-*.png` | Popup screenshots, generated by `scripts/test_site.py` (do not edit by hand) |
| `downloads/` | The release ZIP goes here (added by the Step 4 release script; `*.zip` is gitignored) |
| `vercel.json` | `{"cleanUrls": true}` |

## Release values

The download block in `index.html` is filled in by the release script through `data-release` attributes. Keep them, and keep their contents plain text:

- `data-release="windows-zip"`: `href` becomes `downloads/sidm-v<version>-windows.zip`
- `data-release="version"`: text is the version (may appear more than once)
- `data-release="windows-size"`: text like `1.2 MB`
- `data-release="windows-sha256"`: hex SHA-256 of the ZIP

Until the first release the page shows placeholders (version 0.1.0, "size to be confirmed").

## Screenshots

`python scripts/test_site.py` loads `extension/` in Chromium, opens the real popup and saves `assets/popup-downloads.png` (light) and `assets/popup-this-page.png` (dark), quantised to 64 colours. Re-run it whenever the popup changes. They currently show the M1 popup (empty states) and are placeholders for the finished UI.

## Before launch

- Replace the placeholder contact email `contact@example.com` in `privacy.html` and `terms.html`.

## Test and deploy

- QA: `python scripts/test_site.py` (see `QA.md` for the manual checklist).
